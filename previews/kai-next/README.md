# Kai next: product concept

Open `index.html` directly in a modern browser. It is self-contained and uses no external assets, requests, AI service, microphone, or application-control APIs.

Explore the bug and email examples, source inspection/removal, Write/Ask/Do intents, simulated voice, background task state, result inspection, and guided help. The Capture/Working/Review/Guide controls jump to each state. Appearance offers Obsidian, Paper, and Ink. Larger text and Still motion explore two accessibility options; they do not constitute a full accessibility certification.

All tasks, text, checks, and outputs are fictional and labeled as simulated. The 2.6-second task transition is a demonstration timer, not a latency measurement. The real Kai app was not modified.

Research and implementation recommendations: [Kai product direction](../../docs/research/2026-10-20-kai-direction.md).

Validation: JavaScript syntax and literal DOM reference checks, plus isolated interaction-logic checks with a mocked DOM. Browser visual inspection could not run because connected browsers were unavailable and the native computer-use service failed to start. Responsive CSS and layout therefore still need real-browser inspection, particularly with enlarged text.
