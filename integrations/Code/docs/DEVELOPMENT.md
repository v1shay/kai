# Code

A native macOS home for coding agents. Rust, GPUI/Metal, AppKit window blur, and SQLite. No web view.

```sh
cargo run --bin orbit
```

To build the app:

```sh
./scripts/bundle.sh
open dist/Code.app
```

Requires macOS 13+, Xcode command-line tools, and a Rust toolchain. The app bundle is signed locally for development; it is not notarized for distribution. Install and sign in to your agents through their existing CLIs. Code preserves their environment and authentication. Its Rust launcher supplies a cached child-process PATH for Homebrew and common runtime managers, so Finder launches can resolve CLI interpreters such as Node without a login shell. Code itself has no Node runtime; some third-party CLIs do.

The app icon uses the Bonsai wallpaper artwork. Code explicitly sets its native Dock icon at launch; the bundle also carries the icon for Finder and Launch Services.

## Using Code

- Select a saved project in the left rail to browse its conversations in the sessions column. Use **+** to open a folder, or **All conversations** for recent chats across projects. On first load, projects enter from top to bottom with a soft fade and a small spring movement. Row spacing stays fixed; scrolling or refreshing does not replay the entrance. The Motion setting disables it. Conversation lists inherit the same stagger on project changes and when reopening the column. Opened chat content, submitted prompts, and incoming responses use the same fade/spring; existing text stays settled, streaming tokens do not restart it, and scrolling ends the entrance immediately.
- Use a project's **… → Remove project** to remove it from Code. **Undo** restores it; removal is saved across restarts. Project files and native agent chats stay on disk. Opening the folder again also restores it.
- Use a chat's **… → Delete chat** to remove it from Code's session lists and search. **Undo** restores it; removal persists across restarts and discovery refreshes. The original CLI session and saved history stay intact. Starting, running, and finalizing chats cannot be removed. Both dots menus are compact, translucent, shadow-free popovers beside their trigger; they preserve workspace geometry, dismiss with Escape or an outside click, and stop animating once settled.
- Search, workspace selection, wallpaper controls, and image previews open beside their controls in compact glass dropdowns. They leave the workspace visible, clamp to the window edges, and dismiss with Escape or an outside click. Search and workspace results remain virtualized; the spring transitions stop requesting frames after settling.
- Open **Files** in the chat header or press Command–F (or Command–Shift–E) for the file tree. Folders load on expansion, in pages of 200 entries. Text previews load 64 KiB at a time; type-specific SVGs distinguish code, documents, images, audio, video, PDFs, data, and archives.
- Preview Markdown, source code, and text/data files in the glass inspector. Static PNG/JPEG images render inline; PDFs render one native page at a time with Previous/Next. Audio has local Play/Stop controls, and videos use a native poster with **Open** for playback. Unsupported formats and formatted office documents open in their native viewer. Inline images are limited to 8 MiB and 2048 × 2048 pixels; PDF previews to documents up to 64 MiB and a single 1000 px raster. Video posters depend on Quick Look's format support and fall back to Open after a four-second timeout.
- File citations reveal the file and cited line in Code’s lazy file tree. Web citations open in your macOS default browser.
- Scroll to the top or click **Load earlier messages** to prepend older history. The existing message stays at the same scroll position while the loading indicator animates. **Jump to latest** opens a fresh snapshot.
- Choose Codex, Claude Code, Gemini CLI, OpenCode, AGY/Antigravity, Cursor, or Grok Build from the compact glass composer dropdown. Agent/model choices use each CLI’s native model option. Login locks show green for verified accounts, red for signed-out accounts, and gray for unknown/configured states. Clicking a signed-out or unknown lock opens the native login flow in Terminal; verified accounts are never logged out. Status/model probes run only when requested, with time/output limits and a short cache. Choosing another provider stages it for the next message; it does not interrupt or launch an agent. Send prepares a bounded context handoff and submits it together with that message in one destination invocation, preserving the visible chat, project, checkout, and compatible images. Changing models applies on the next turn of the same native session.
- All seven provider SVG marks appear in the bottom agent strip, including Cursor and Grok Build. Unavailable CLIs are dimmed; clicking the strip opens agent settings.
- **Read only** uses Codex’s OS sandbox or the other provider’s native plan/permission policy; **Build** permits workspace edits while retaining native approvals. Codex App Server, Claude’s bidirectional protocol, Gemini ACP, and an authenticated private OpenCode server connect tool approvals and questions to the waiting tool. A pinned glass tray keeps decisions reachable during long output; opaque per-run tokens reject stale controls. Secret answers are masked and excluded from drafts/history. OpenCode plan mode is a permission policy, not an OS sandbox; Code preserves native deny rules. Cursor now uses its installed native ACP interface for session/model/mode negotiation, approvals, questions, plan decisions and child progress. AGY and Grok remain headless adapters; their interactive approval parity is tracked separately.
- The first prompt in an imported Codex chat uses native App Server `thread/fork` to retain its history in a Code-owned continuation, leaving another client’s writer open. Later prompts resume the new native ID. Code retains its UI chat, model choice, lazy history, and local messages; rediscovery/restart cannot restore the parent ID or duplicate the child. If another client later owns that child, a compact **Continue with copy** action provides recovery. Native error logs become one concise typed failure, without a duplicate composer banner.
- Gemini/Cursor workspace-trust failures offer an anchored **Trust & retry** control. Confirmation permits native project settings/hooks while retaining tool-permission mode; Cursor may persist its own workspace trust marker. Cancelling retains the draft and does not grant trust. Other failures appear as typed chat cards and restore the submitted prompt/images without replacing new typing.
- Enter sends; Shift–Enter adds a line. The send button becomes Stop during a run. Up to four conversations can run simultaneously, including different CLIs working in the same project. Each thread retains its own agent and saved model choice.
- Click the microphone to dictate with Apple Speech. The packaged app asks for macOS microphone and speech permission. Recognition runs on device when supported, with Apple’s service as the native fallback. Accepted words append without replacing or deleting composer text; pauses restart recognition on the same microphone engine. Manual edits remain authoritative, the caret stays unselected, and the latest wrapped line stays visible. Switching chats, sending, Escape, or clicking Stop ends capture. Dictation writes a draft; it never sends automatically.
- Drag images into the composer or click the paperclip. Small cached thumbnails enter with a finite spring; click for a bounded preview and hover for removal. Up to four PNG/JPEG/WebP/GIF/HEIC images are imported as private managed PNGs, with a 16 MiB input-file and 32 MiB prompt limit. Codex, Claude Code, Gemini (when advertised), and OpenCode receive native image input; unsupported providers retain the draft and explain the limitation. Claude’s encoded native input has an additional 10 MiB limit. Submitted images remain available in saved history; unsent images are cleaned up after their last draft/preview releases them.
- Command–T starts a conversation, Command–E hides or reopens the conversations column, Command–S searches, Command–A opens Settings outside text fields (and selects all text inside them), Command–F toggles Files, and Command–D toggles Changes. Command–Shift–A remains a Select All alias in text fields. Command–N/Command–K remain aliases for new/search; Command–B toggles the project sidebar, and Escape dismisses a picker. When collapsed, the sidebar has a reopen button in the left header. Command–W closes the window; Command–M minimizes it. The native traffic lights are hidden, and empty title/header regions remain draggable.
- Open **Settings → Wallpaper**, or use the picture icon in the chat header. The bundled ASCII Bonsai at Sakura Sunset artwork is the default. Choose, replace, or remove project artwork; select Monocode's None, Dither, ASCII, Halftone, Scanlines, or Haze effect; choose empty chats only or all sessions; adjust empty/session visibility separately from 5–65%. Settings and managed images persist per project.
- During startup and conversation loading, the actual provider SVG spins in place with smooth acceleration, then springs upright when ready. It never blocks interaction or holds a minimum loading delay. It pauses when inactive and respects Motion and system Reduce Motion.
- The sparkle button controls motion, including GIF playback. Set `ORBIT_REDUCE_MOTION=1` to start with motion off. Static artwork and the last GIF frame remain visible when motion is disabled or the window loses focus.

Discovery reads Codex’s saved project names, membership metadata, and thread index, plus Codex/Claude/Gemini log metadata, OpenCode's read-only session index, and common development folders. Reads and directory scans are bounded; credentials stay with their CLIs. Saved project grouping and actual worktree execution directories are kept separate. Opening a conversation reads its latest bounded page directly from the native transcript and retains its original CLI session ID. Older pages load on demand. Refresh discovers changes made outside Code. Source transcripts remain owned by their CLIs. New AGY, Cursor, and Grok conversations persist locally and resume using returned native IDs.

The **+ beside Chats** starts an unprojected conversation without inheriting the selected repository. Each standalone chat gets a separate UUID workspace under `~/Library/Application Support/Orbit/Chats`, created on the existing background launch task when you first send. Project-row + actions stay project-scoped. Navigation grouping, actual CLI working directory, unsent drafts and native resume IDs survive saving/reopening; rediscovery keeps managed standalone workspaces under Chats rather than listing them as projects. Starting another chat in that section chooses a fresh workspace.

The interface translates [Monocode’s](https://github.com/hardbeat920/monocode) layout, spacing, typography, and glass tokens into GPUI: a 200 px project rail, 260 px sessions column, compact tabs and headers, and a small composer. The native chrome adapts Monocode's 24 px WindowServer blur and semantic AppKit backing, with material fallback if the private blur API is unavailable; translucent GPUI panels expose it. Provider SVGs preserve the real marks’ geometry; interface icons use Monocode’s Hugeicons library. See [asset provenance](assets/NOTICE.md) and [design tokens](assets/DESIGN-TOKENS.md). Sidebar rows fill the inset list width and truncate long labels; session metadata uses explicit line heights. Chat cards and hover states use translucent ink instead of opaque black fills. Spring transitions settle and stop requesting frames. Artwork uses a long, curved transparency fade with progressively stronger haze toward the bottom, while the top stays crisp. This fade composes with every selected effect and GIF frame after cover-cropping. Its blur uses a bounded 256 px worker-side raster, and blending shares the existing alpha/upload pass. Resize work is debounced, decoded static sources are reused, and GIF playheads survive layout changes.

Imported approvals, injected harness context—including recommended-plugin lists—and internal helper chats are filtered, including fragments of giant cached messages. Ordinary user JSON, HTML, inline code, and fenced examples remain intact. Markdown supports inline formatting, links, numbered lists, tables, and highlighted code; actual tool calls appear as expandable activity rows. Conversation drafts and unsent image attachments survive tab/project switches. Codex realtime speakers, delegation, completion/status events, and structured questions become glass transcript cards. Speaker text retains Markdown/file links. Question choices place a reply in the composer for review; imported questions cannot resume a historical tool call. Live questions use the pinned native request controls, while historical questions remain read-only. Code does not implement a live Codex audio conversation transport. See [the complete capability audit](FEATURE-COVERAGE.md) for provider-specific gaps and verification evidence.

## Commands, usage, and context handoff

Codex `/status` uses live App Server account/model/quota data, without an inference request. Claude models and commands come from SDK initialization; Gemini uses its negotiated models/commands and OpenCode its server catalog. `/compact` invokes real Codex context compaction, `/steer <instruction>` addresses an active Codex turn, and `/interrupt` sends its native interrupt. `/skills`, `/mcp`, and `/plugins` inspect project-scoped native inventories. `/terminal <command>` uses Codex `command/exec` with the selected read-only/workspace-write sandbox, blocked network, streamed output and authoritative exit status; Stop or `/interrupt` terminates the owned process. It creates no model prompt or native chat; it is a command runner rather than a full terminal emulator. Native CLI commands are revalidated against fresh provider advertisements before dispatch.

Type `/` in the composer for an anchored glass dropdown. Up/Down selects a command and scrolls its virtual list, Enter runs it, Tab completes its name, and Escape dismisses without clearing the draft. Paths and code retain normal editor navigation. The local catalog contains 27–29 controls per agent; commands marked **Code equivalent** invoke Code's implementation of a documented terminal action, while **CLI** entries run through the installed agent.

| Commands | Behavior |
| --- | --- |
| `/new`, `/clear`, `/resume`, `/search`, `/sessions` | Start fresh, find saved conversations, or toggle their list |
| `/projects`, `/files`, `/diff`, `/latest`, `/sidebar` | Navigate the workspace, current Git changes, and recent history |
| `/agent`, `/model [id]`, `/handoff [agent]` | Choose an agent/model or explicitly transfer context |
| `/status`, `/context`, `/usage`, `/copy-session` | Inspect provider/session data or copy the reported native ID |
| `/permissions`, `/read-only [prompt]`, `/edit` | Use the existing native permission policy; optionally submit a read-only prompt |
| `/settings`, `/wallpaper`, `/motion`, `/dictate`, `/stop`, `/help` | Native appearance, input, cancellation, and command controls |
| `/attach` | Image input for Codex, Claude Code, and OpenCode |
| `/delegate <task>` | Request a provider-native child through Codex, Claude Code, or OpenCode, keeping the result in this chat |

Provider aliases include Claude's `/cost`, Gemini's `/stats`, OpenCode's `/models`, and `/plan` for Claude, Gemini, OpenCode, AGY, and Cursor. Grok's `/cost` is a Code control. `/model <id>` accepts only models from the cached CLI catalog; `/model default` restores the CLI default. These controls do not send unsupported terminal UI commands to a model.

Claude additionally advertises headless commands through `system/init.slash_commands`. After its first initialized turn in a checkout, Code adds the validated advertised commands, including `/compact` and available skills/MCP commands. Names are scoped to Claude and the checkout, deduplicated, and bounded to 128 entries. Existing Code controls take precedence. Native commands run between turns with the returned native session ID, reject images, and must be confirmed by the fresh CLI initialization; compaction requires prior native history. Other adapters do not advertise a verified headless slash catalog, so Code exposes its working controls instead of forwarding arbitrary terminal commands. See [Claude's headless command protocol](https://code.claude.com/docs/en/agent-sdk/slash-commands), [Codex CLI options](https://learn.chatgpt.com/docs/cli/reference), [Gemini headless mode](https://geminicli.com/docs/cli/headless/), and [OpenCode CLI options](https://opencode.ai/docs/cli/).

**Status · context** opens the same glass panel as `/status`. Each conversation retains its own provider-reported usage snapshot: tokens, cached input, context/window sizes, cost, and rate information when supplied. Counters retain the CLI's reporting scope; unreported fields are hidden. Quota cards show the remaining percentage, a readable provider/bucket name, and a separate reset line when reported. Staging another provider never relabels the current provider's counters. A last-request context count is not a live remaining-budget estimate. AGY currently has no verified token-counter schema. There is no tokenizer or background account polling.

Choosing another agent in an existing chat, or using `/handoff`, only stages the destination. The existing invocation continues. On Send, Code captures the instruction, model, policy, images and attached context, prepares bounded recent history on a worker, commits the destination binding and launches one invocation containing both the handoff and the submitted instruction. The visible chat ID, tab, title, prior rows and lazy history stay in place. Edits made during preparation remain an unsent draft. Preparation/binding failures preserve the submission and hold queued work for review. Native source transcripts remain intact; durable aliases prevent rediscovery from adding duplicate chats. Assistant turns retain their original provider identities across repeated switches and restart. Packets are capped at 48 KiB; one recent page decodes at most 256 KiB. This does not migrate hidden reasoning, provider caches, live tools, or an entire enormous transcript. Model changes within one agent reuse its native session on the next turn. After a provider limit/error, choose another agent explicitly; automatic quota-based fallback is not configured. Native permissions, model availability, and account limits continue to apply.

The small subagent button prefixes the current draft with `/delegate`; submitting asks the current parent harness to launch one native child and wait for its result. A request is not proof of launch. Only observed native events create progress/result cards, and child failure does not fail the parent. Codex App Server supplies native child-thread and collaboration events. OpenCode’s global event stream follows children across working directories, filters reasoning from assistant prose, and keeps their approvals on the owning runtime. Claude parent-tool correlations retain child identity. Bounded expandable reports keep older history cold. Custom child definitions and every provider’s child-control surface are not yet fully exposed.

Catalogs initialize once; filtering touches only the small active catalog. At most seven rows paint in the command dropdown. Usage parsing shares the existing protocol pass; completed reports save on the state worker. Handoff loading/serialization also stays off the UI thread, with at most eight shared packets retained in the frontend. No new dependencies, per-frame discovery, or idle polling loops are added.

## Responsiveness by construction

The sidebar and transcript use GPUI virtual lists. Large Markdown/code blocks become bounded rows; completed responses and lexical syntax highlighting are processed on a dedicated state worker. Inline styles advance through long paragraphs in one ordered pass, and links share their URL allocations across rows. A bounded unfinished output tail is parsed off the UI thread while streaming. Each run has at most one pending parse; later deltas coalesce, and stale results are discarded. Complete responses stay on the state worker. UI invalidation touches changed list ranges. The state worker owns SQLite in WAL mode; the UI performs no database queries or filesystem scans. Discovery writes summaries in one transaction, skips unchanged rows, and updates full-text indexes only when indexed content changes. Superseded queued chat, project, and search reads are discarded before expensive work; writes remain ordered.

History pages decode at most 256 KiB, with up to 200 source chunks requested per page. Native transcripts use a reverse cursor with 64 KiB input buffers. A single oversized JSON record is scanned into a disk-backed text-span index without allocating its complete body; later pages decode only the requested slices. Fenced code keeps its language and code styling across page boundaries. Local saved messages use incremental SQLite BLOB reads. Chats and individual messages above 16 MiB are supported. Distant decoded pages are evicted after eight resident pages, while visible/nearby rows stay resident; a small disk cache reloads previous pages without rescanning the transcript.

OpenCode history reads its native SQLite database without writing it or holding a read transaction between pages. Metadata arrives in batches of at most 128 rows. Small parts decode directly; oversized parts stream to private temporary envelopes for bounded decoding. A captured maximum key excludes newer turns. Already visited pages stay deterministic. Unvisited older rows can reflect subsequent edits made by OpenCode itself.

Background artwork supports GIFs, SVGs, and static formats understood by macOS ImageIO, including PNG, JPEG, WebP, HEIC/HEIF, AVIF, BMP, TIFF, and ICO where supported by the installed OS. Image decoding, Monocode's pixel effects, and Haze blur run on a dedicated worker. Static rasters are capped at 2048 px; GIFs stream one frame at a time at 512 px while preserving frame order, delays, and repeat counts. Playback pauses on focus loss, hidden scope, and reduced motion. Encoded sources are limited to 32 MiB and GIF canvases to 2048 × 2048 pixels. SVG sources have a separate 4 MiB limit, with bounded embedded rasters and no external resource loading; compressed SVGZ is unsupported.

Agent stdout/stderr are drained away from the UI using pipe readiness, with a 100 ms lifecycle check for cancellation and child exit. The UI awaits a coalesced readiness notification and batches actual output into a frame; quiet agents have no recurring UI polling timer. Queues apply backpressure at 128 events and 2 MiB of payload, permitting one larger replacement when empty within the live response limit. Producers wait on a condition variable when the queue is full. Stop and window/application teardown cancel process groups and reap children. Parent exit detection retains process-group ownership until cleanup, terminating remaining owned descendants before reaping; cancelled input writers stop even with a full pipe. Empty successful exits report a failure instead of a silent completion. Motion runs only during transitions or active work; idle windows stop requesting animation frames.

Background imports reuse the first prepared raster rather than decoding twice; unchanged settings do not trigger writes. File-preview cancellation follows selection ownership, and superseded video helpers are terminated and reaped. Native ImageIO/CoreGraphics/AppKit APIs and macOS audio/Quick Look helpers remain in use for efficient platform media support. The application runtime is Rust/GPUI, including dictation, image imports, model/account controls, and typed interaction rendering; Swift is used only by the optional build-time icon generator. Apple audio buffers feed the recognition request directly. Stopped capture owns no polling task, and image cleanup is enqueued to a bounded sleeping worker.

Practical navigation limits: 6,000 global summaries, up to 1,000 indexed summaries per selected project, and 64 KiB composer drafts. Live responses no longer fail at 16 MiB: the runtime retains up to 256 KiB in memory before spilling to a private owned file, while the UI retains only a 64 KiB live tail. Completed large responses stream into SQLite in 64 KiB chunks and reopen through the existing lazy reader; they are not parsed in full on completion. Large streamed bodies are excluded from full-text indexing to avoid materialization; their chat titles remain searchable. Live protocol records have no fixed byte-size ceiling: records above 1 MiB spill to an unlinked private temporary file on the runtime worker, then decode a bounded view of response text, identities, statuses, interactions, and usage. Unused tool/binary payloads are consumed without creating giant JSON objects; exceptionally large individual fields receive bounded previews with a status notice. Oversized records can require an initial background scan before the first page appears. Unopened transcript bodies are loaded only on selection; search covers titles and indexed messages already persisted in Code, not all unopened native transcript bodies. Native request dialogs are implemented for Codex, Claude, Gemini, OpenCode and Cursor. AGY/Grok interactive permission parity remains future work.

The existing bundle identifier and data folder are retained so chats, settings, and macOS permissions survive the rename. History is saved to `~/Library/Application Support/Orbit/history.sqlite`. Set `ORBIT_DATA_DIR` to isolate a test run.

Code restores saved window geometry and mode, sidebar, project, up to eight tabs, the active agent/model, edit mode, drafts, and file/Changes panels. Inactive transcript bodies stay cold. The active reading position restores from one bounded page plus durable cursor metadata, without replaying earlier pages. Changed sources or checkpoints beyond the 2 MiB navigation budget reopen recent messages with a notice. OpenCode database writes can conservatively invalidate its checkpoint. Window coordinates adjust to displays that are currently connected.

**Settings → Appearance** provides independent glass blur-radius (0–64 px) and opacity controls; Wallpaper remains accessible there and from the chat header. Changes are coalesced into atomic background saves at `~/Library/Application Support/Orbit/workspace.json`, with no idle save timer. Opacity affects panel tint, keeping text and controls legible; blur uses the native backdrop with an AppKit fallback where the optional radius API is unavailable.

## Compacted Codex history and reconnects

Code opens Codex's `.jsonl.zst` archives as well as plain JSONL. The state worker resolves the native indexed location, its compressed sibling, or an exact-ID archived location before opening a chat. A selected compressed archive is streamed into a private seekable temporary source with a bounded decoder window and 64 KiB chunks; message decoding still follows the existing 256 KiB page budget. The first archive open requires a sequential preparation pass. Scroll navigation and saved viewport restoration reuse that source through private artifacts, without decompressing it again. Superseded selections cancel archive preparation, and the final owner releases its temporary file. Native archives remain unchanged.

Codex's exec JSONL `error` event also carries reconnect diagnostics. Code keeps these as live statuses while the CLI retries, preserves partial output, and waits for `turn.completed`, `turn.failed`, or process exit. It never automatically resends the prompt. An exhausted connection failure still appears as an actual failure.

Read-only opt-in checks are `engine::tests::installed_old_sessions_resolve_and_selected_archives_load` (explicit `CODE_HISTORY_AUDIT_HOME`/`CODE_HISTORY_AUDIT_DB`) and `runtime::history::tests::installed_codex_archive_opens_and_paginates` (explicit `CODE_ARCHIVE_SMOKE_PATH`). These inspect selected local metadata/history and never invoke a model. The decoder's MIT/BSD notices are included under `LICENSES/` and in the app bundle.

## Recoverable native workflows

New Rust modules keep orchestration separate from native transports: `teams`/`team_ui` own bounded user-assigned team plans; `prompt_queue`/`queue_ui` retain explicit follow-ups; `context_refs`/`context_ui` own cross-project excerpt snapshots. All actual runs still use the existing provider runtime and owning request IDs. `/team`, `/attach-chat`, and `/shell` are Code controls rather than model prompts. Read-only team members overlap under the shared four-run cap; overlapping workspace writers serialize. Restart holds unfinished work.

`checkpoints` streams content-addressed before/after files with SQLite manifests, cached signatures, conflict validation and per-file restore journals. `checkpoint_ui` requires an explicit preview and restore action. New runs and terminal startup wait while checkpoint work is active; Stop remains available. Capture/seal/restore/forget never run in a paint callback. Graceful quit and view release cancel pending launch tokens as well as owned handles. Full crash recovery distinguishes resumable applying journals from interrupted attribution.

`terminal` uses the pinned Rust Alacritty engine and real native PTY; `terminal_ui` paints visible style runs, forwards IME/keyboard input and allocates a shell only on request. A shared startup cancellation token reaches pre-exec, and owned-child guards retain cancellation/reaping on races. See [NATIVE-TERMINAL.md](NATIVE-TERMINAL.md) and [CHECKPOINTS.md](CHECKPOINTS.md).

Local prompt display and actual provider input can differ because of attached context/team/handoff envelopes. An atomic saved-message association keeps only bounded native-input SHA-256 metadata and lengths/bookends; lazy seam comparison verifies the complete native bytes in bounded spans. Legacy prompts retain exact streamed SQLite BLOB comparison. This avoids storing a second full prompt or accepting substring matches.

Apple Speech tests cover pauses, task restarts, timestamp-disjoint phrases, shorter ASR corrections and Stop flushing. Native acoustic/device/permission testing remains a separate signed-app check. Clipboard raster imports and queued-image restoration use the existing bounded managed cache and reject symlink/parent-path escapes.
